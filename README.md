# Молочные Традиции — каталог 2.0

Новая версия оптового каталога на Next.js с мобильным интерфейсом, отдельной базой товаров и закрытой админ-панелью.

## Что уже перенесено

- 152 товара и 16 категорий из старого `index.html`.
- 239 существующих фотографий привязаны к конкретным товарам.
- 72 товара без фотографий показывают заглушку «Фото скоро».
- Оригинальные фотографии сохранены в `Photos`, оптимизированные версии с прозрачным светлым фоном находятся в `public/products`.
- Старый `index.html` оставлен как исходный архив, но при сборке Next.js не используется.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Каталог: `http://localhost:3000`

Админка: `http://localhost:3000/admin`

Пока Supabase не подключён, каталог использует локально перенесённые данные, а `/admin` показывает инструкционный экран.

## Подключение Supabase

1. Создать проект на [supabase.com](https://supabase.com/).
2. Открыть **SQL Editor** и выполнить целиком `supabase/schema.sql`.
3. Затем выполнить `supabase/seed.sql` — он добавит все перенесённые товары и фотографии.
4. Открыть **Authentication → Users → Add user**, создать администратора с email и сильным паролем. Автоматическое подтверждение email для этого пользователя можно выполнить при создании.
5. Скопировать UUID созданного пользователя и выполнить в SQL Editor:

```sql
insert into public.admin_users (user_id)
values ('UUID-ПОЛЬЗОВАТЕЛЯ');
```

6. В **Authentication → Providers → Email** отключить публичную регистрацию, если она включена. Пользователей следует создавать только вручную из панели Supabase.
7. В **Project Settings → API** скопировать Project URL и Publishable key.
8. Создать `.env.local` на основе `.env.example`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

Не используйте и не публикуйте `service_role` или Secret key. Сайту нужен только Publishable key; изменение данных дополнительно защищено политиками RLS.

## Двухфакторная защита

После первого входа откройте в верхней панели админки **Защита**. Отсканируйте QR-код в Google Authenticator, Microsoft Authenticator или другом TOTP-приложении и подтвердите шестизначный код.

После подключения второго фактора:

- при каждом новом входе после пароля потребуется одноразовый код;
- правила базы не разрешат изменение товаров с сессией первого уровня;
- просмотр опубликованного каталога останется публичным.

## Развёртывание на Vercel

1. Заменить содержимое существующего GitHub-репозитория файлами этой папки и отправить commit в основную ветку.
2. Vercel автоматически определит Next.js по `package.json`; `vercel.json` дополнительно фиксирует этот режим.
3. Сначала проверить Preview Deployment.
4. В **Vercel → Project Settings → Environment Variables** добавить три переменные из `.env.local`, но для `NEXT_PUBLIC_SITE_URL` указать настоящий адрес сайта.
5. Выполнить повторное развёртывание после добавления переменных.

Изменения кода по-прежнему публикуются через GitHub. Изменения цен, наличия, отметок и фотографий через `/admin` сохраняются в Supabase и не требуют commit.

При добавлении фотографии админка по умолчанию автоматически убирает светлый фон, связанный с краями снимка, и сохраняет прозрачный WebP. Белые части упаковки внутри объекта остаются нетронутыми. Для сложного снимка обработку можно отключить переключателем над фотографиями.

Админка принимает фотографии JPG/JPEG, PNG и WebP размером до 10 МБ. Товар можно удалить целиком кнопкой в нижней части его карточки; перед удалением требуется подтверждение.

## Обслуживание перенесённых данных

- `pnpm migrate:legacy` повторно извлекает данные из старого `index.html`.
- `python -m pip install -r scripts/requirements-images.txt` устанавливает инструменты обработки фотографий (нужно сделать один раз).
- `python scripts/optimize-images.py` создаёт компактные WebP-копии и автоматически убирает у них светлый фон.
- `node scripts/generate-supabase-seed.mjs` обновляет `supabase/seed.sql` из локальных JSON-файлов.

После подключения рабочей админки эти команды для обычного обновления каталога больше не понадобятся.
